## 這次修正

- Git 範圍參數、`src/` 與 `./src` 等價處理，以及 rename 分批時保留完整配對。
- 檔案變同名目錄造成敏感子檔案外洩：改用同次 Git 呼叫的 NUL metadata 核對精確端點，再回傳 patch。
- 停用外部 diff/textconv 與子模組內容展開；任一批拒絕時不回傳部分內容。
- 修正 rename 方向、中文檔名解析、UTF-8 分頁破字與跳過 bytes。
- Git 執行失敗與「不是 repository」分開回報。
- `.c2cignore`、`.c2c.json`、`package.json` 改由專用 reader 讀已核對的 descriptor，以 BigInt 比對檔案身分。
- 修正根目錄與合法 `..notes` 的錯誤拒絕，及名稱截斷產生半個 Unicode 字元。
- 評審原文引用／字數改用機械核對；清理須等外掛列表與設定更新完成。

上述 Git 問題位於 legacy helper；目前 C2C 本來就只供應精確快照，不開放 live `git_diff`。
原始 Workspace 的 hardlink 限制也不等於本版漏洞：快照建立已拒絕多重連結檔案。

## 量測界線

- 本批沒有確認顧問入口的額度歸屬。一般 Chat 與 ChatGPT Work 必須區分；官方目前明示 Work 與 Codex 共用額度。
  只有轉交到獨立額度入口，才能以轉移工作量為節省機制；淨收益仍須扣除 Codex 的交接與驗證成本。
  1.92 倍耗時不能證明額度消耗增加。來源：[官方額度規則](https://learn.chatgpt.com/docs/pricing)（2026-08-31 核對）。
- 這是已知任務、暖機環境的流程比較，不是盲測、隨機對照或純模型排名。
- ChatGPT 帳號個人化與 CLI 隔離設定不同；requested model/effort 相同，但實際 backend 身分未知。
- 原 R03 Ordinary 計時過早結束而作廢；核准後另跑一次，發生在 R10 後，偏離交替順序。
- 作廢那次至少耗費 5.51 分鐘，另有未計時複核成本；均未塞入新計時，也未隱藏。
- 以上不含共同整合與整批驗收時間。原始批次的 27 次讀取、Ordinary 五次失敗、C2C 一次設定失敗保留，不混成新批次零失敗。
- 本機原生 file-symlink 受 EPERM 限制；POSIX flags 僅模擬測試。專用 config reader 不等於任意可變根目錄的完整 sandbox。
- 前兩組舊評審格式未含後加的引文字段；獨立複核已從原始讀取輸出確認完整來源、答案與裁決均在停表前，沒有回填舊計時。
