# Windows Portability Repair

## Scope

Continue the usable, opt-in C2C workflow. This repair addresses installation and
test portability reported during a secondary Windows machine's takeover. It does
not reopen the completed ten-pair external comparison, install a global skill,
or change the approved data boundary.

## Evidence Before Changes

The secondary machine tested commit
`7cf5eb67bf94fabababb99ec62f6aa46a082607d`: build passed; the full suite had
402 tests, 391 passed, 11 failed, no skips. The CLI file passed when rerun alone.
That rerun does not erase the full-suite failure.

The maintainer then created an independent short-path checkout with no existing
`node_modules` or `.tooling`, using Node 24.19.0 and pnpm 11.19.0. Frozen-lockfile
installation downloaded all 156 packages, reused zero, and used its own store.
It did not link to the original checkout's dependencies. Build passed; the
unchanged baseline passed 397 tests, failed zero, and skipped five of 402.

## Issues And Boundaries

| Reported issue | Confirmed evidence | Repair and remaining limit |
| --- | --- | --- |
| Missing `.tooling` | The first Windows-driver test listed the directory without handling an absent parent. | Missing cache now means an empty fixture list. The regression creates its isolated parent under the repository root and verifies that listing does not create a cache. Independent review caught and corrected the regression's own former cache dependency. |
| CLI full-batch failure | A controlled 5,100 ms startup delay expired the former five-second fixture. This demonstrates a timing risk, not the original secondary-machine cause. | Test-only lifetime is now 15 seconds, with a 25-second child timeout. Actual expiry, clean exit, and lock cleanup assertions remain. Production snapshot lifetimes are unchanged. This is bounded timing headroom, not a guarantee under arbitrary load. |
| Nine empty PowerShell outputs | The secondary-machine report records empty stdout with exit 0. The maintainer did not reproduce those failures. | The test extractor uses an ASCII `.ps1` file and explicit Windows PowerShell path, a five-second bound, and null-safe process/output diagnostics. Empty-success and forced-timeout regressions were added. No production helper function changed; the secondary machine remains unverified. |

Windows-driver test subprocesses also use `process.execPath` instead of a
maintainer-specific Node installation path. No security assertion was removed.

The secondary-machine detailed JSON logs remain on that machine. The synced
takeover report is retained unchanged. No antivirus, execution-policy, or ACL
root cause is asserted without evidence.

## Release Verification

| Run | Total | Passed | Failed | Skipped |
| --- | ---: | ---: | ---: | ---: |
| Unchanged baseline, independent fresh install | 402 | 397 | 0 | 5 |
| Repair before independent-review correction, fresh install | 404 | 399 | 0 | 5 |
| Post-review full rerun, fresh install | 404 | 398 | 1 | 5 |
| Final fresh-install rerun with local process diagnostics | 404 | 399 | 0 | 5 |
| Final maintainer checkout, standard full run without diagnostics | 404 | 399 | 0 | 5 |

The failed post-review run reported `AUTH_STORE_UNAVAILABLE` in the
`logs unique request ids, approved paths, serialized byte counts, results, and time`
session test. It took 6,085 ms; its isolated rerun passed in 1,186 ms. This timing
is consistent with the five-second PowerShell bound, but the original underlying
error was not captured, so timeout is not established as the root cause.

The final diagnostic run observed 366 PowerShell invocations, maximum 1,200 ms.
Its only timeout was the deliberately forced transport regression (270 ms).
The local diagnostic wrapper records only duration, status, signal, error code,
and output byte counts, never arguments, input, content, credentials, or paths.
It does not change timeout or return behavior. Its raw trace stays local.

The intermediate failed run is retained, not erased by later passes. The
intermittent auth-store failure is an open reliability limitation. No storage
checks, timeouts, or ACLs were relaxed to make it pass.

Both checkouts built successfully. The final standard maintainer-checkout run
passed without diagnostic instrumentation. Both `review prepare --help`
and `review run --help` passed. Independent code review confirmed the cache
regression correction and retained expiry, cleanup, and strict output assertions;
this is not an independent production-security certification.

## Usage Decision

The existing C2C decision remains: usable on demand for approved public or
non-sensitive fixed snapshots; Ordinary Codex is the default. Say `C2C` plus the
project and question to invoke the established workflow. This patch does not
claim a new external end-to-end acceptance run, measured quota savings, or
universal Windows containment.

The user is not required to operate the secondary machine for this repair.
Its browser login, cloudflared installation, connector, and repaired test suite
remain unverified there. Five native file-symlink skips on the maintainer machine
remain skips, not passes. Keep the documented short local checkout path and all
snapshot, ACL, token-revocation, and cleanup checks.
