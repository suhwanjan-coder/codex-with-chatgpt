# Documented security boundary coverage — 2026-10-23

Audited source: `625053d`, on Windows 11 / Node 24.19.0. This is an offline
coverage audit, not a security certification, live ChatGPT review, or G7 pass.
Only synthetic fixtures and existing loopback fixtures were used. No external
transport or settings changes were authorized. The three excluded files were
read, but not edited: `src/review/private-storage.ts`, `src/review/session.ts`,
and `tests/review-private-storage.test.ts`.

The matrix includes executable guarantees and operator obligations from all
three requested documents. Repeated claims are consolidated; historical scores,
run IDs, package versions, examples, and aspirations are not new enforceable
security guarantees. Protocol instructions without a parser are retained as
explicit gaps, not counted as covered by a string search. Document line numbers
refer to the unchanged source documents at the audited commit.

`COVERED` means tests exercise the stated executable boundary, including a
negative case where applicable. `PARTIAL` means only part is exercised or a
native/operational qualification remains. `UNCOVERED` means there is no enforcing
test for the stated obligation. A skipped test is not a pass. These labels assess
test coverage, not proof against every attack. `NEW` identifies additions in this
change. Before means the original tests; status means after this change and its
regression fixes. Source inspection supplements, but never substitutes for,
passing test evidence.

76 consolidated claims: before **33 COVERED / 33 PARTIAL / 10 UNCOVERED**;
after **56 COVERED / 14 PARTIAL / 6 UNCOVERED**. Forty-two new test cases
(including parameterized cases) move 23 claim rows to COVERED and strengthen
several remaining PARTIAL rows. Remaining
rows explicitly distinguish unavailable native evidence, excluded storage work,
document drift and operator obligations.

## Findings, scope decisions and verification

Two executable regressions were reproduced and fixed separately from tests:

1. Legacy `Workspace.readFile` returned a 2,048-byte first line with a 1,024-byte
   requested cap. The regression expected FILE_TOO_LARGE but the promise resolved.
   The fix rejects an individually unreturnable first line and closes its read
   resources; ordinary UTF-8 pagination retains its existing assertions.
2. Legacy OAuth exchanged a valid code with an omitted redirect URI: expected
   400, received 200. The fix requires the exact stored redirect URI. The hardened
   review OAuth path already required this binding.

The admin test initially expected 404 for forwarded requests; inspection showed
an earlier 403 LOCAL_REVIEW_ONLY guard. Only the new test expectation was corrected
to assert that exact earlier denial. No production weakening was needed.
